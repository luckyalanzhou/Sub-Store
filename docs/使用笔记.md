# 使用笔记

在 LuCI 的「服务 → sub-store」顶部查看状态，在页面底部执行容器操作。

首次运行 `.run` 安装插件后，服务状态为「尚未安装」。点击「安装」才会准备镜像并启动容器。

| 状态 | 可用操作 |
| --- | --- |
| 尚未安装 | 安装 |
| 运行中 | 升级/应用、停止、重启 |
| 已停止 | 升级/应用、启动、删除 |

「安装」和「升级/应用」会保存并应用表单设置。「升级/应用」分别检查镜像和插件版本。容器配置有变化时会重新部署，原先停止的容器会在健康检查后恢复停止状态。操作进度和结果可在「日志 → 维护日志」查看。

「删除」需要确认，只删除已停止且有独立数据挂载的容器。镜像同时满足官方仓库归属明确、没有其他仓库引用、没有其他容器使用时，才会尝试清理。UCI 配置和持久化数据会保留，可再次点击「安装」恢复服务。

「镜像」写入 UCI 的 `sub-store.main.image`，默认值为 `xream/sub-store:latest`，也支持该官方仓库的标签或 SHA-256 摘要。「API 密钥」写入 `sub-store.main.api_path`，须为 48 位十六进制字符。设备脚本在部署时重新校验这些设置。

## VPS 独立部署

VPS 用户使用 `scripts/sub-store-vps.sh` 提供的 `sub-store-vps` 命令；该入口不使用 LuCI、UCI 或 iStoreOS `.run` 安装器。支持范围与完整参数见 [README 的 VPS 部署说明](../README.md#vps-独立部署可选)。脚本只接受 Docker 官方安装文档支持的发行版版本；Docker 不存在时通过 Docker 官方 APT/RPM 仓库安装并启动。运行命令需要 root 权限。

从 VPS 执行以下任一下载流程，后续按向导输入 DDNS 域名或接受默认路由 IPv4，其他选项可直接回车采用默认值：

```sh
# curl
curl -fsSL https://raw.githubusercontent.com/luckyalanzhou/sub-store/main/scripts/sub-store-vps.sh -o /tmp/sub-store-vps.sh && \
sudo install -m 755 /tmp/sub-store-vps.sh /usr/local/sbin/sub-store-vps && \
sudo /usr/local/sbin/sub-store-vps install
```

```sh
# wget
wget -qO /tmp/sub-store-vps.sh https://raw.githubusercontent.com/luckyalanzhou/sub-store/main/scripts/sub-store-vps.sh && \
sudo install -m 755 /tmp/sub-store-vps.sh /usr/local/sbin/sub-store-vps && \
sudo /usr/local/sbin/sub-store-vps install
```

主要管理命令：

```text
sudo sub-store-vps status
sudo sub-store-vps config show
sudo sub-store-vps config set <key> <value>
sudo sub-store-vps api-path                 # 显式读取私密 API 路径
sudo sub-store-vps api-path rotate
sudo sub-store-vps url [--host <IP-or-domain>]
sudo sub-store-vps start
sudo sub-store-vps stop
sudo sub-store-vps restart
sudo sub-store-vps update
sudo sub-store-vps logs [--follow]
sudo sub-store-vps remove [--delete-data] [--yes]
```

`config show` 隐藏 API 路径；`api-path` 才会输出路径。安装摘要包含完整管理网址，网址同样包含私密路径，不要公开分享。配置保存在 `/etc/sub-store-vps.conf`，权限为 `0600`；数据保存在 Docker 命名卷 `sub-store-data` 并挂载到 `/opt/app/data`。默认移除保留数据；只有加 `--delete-data` 才会删除卷，非交互模式还须加 `--yes`。安装时发现冲突的旧 Docker/Podman/containerd/runc 包会停止，不会自动卸载它们。

前端默认发布到 `3001` 所有接口，后端 API 默认发布到 VPS 的 `127.0.0.1:3000`。启用 `--backend-lan-access 1` 会将后端绑定到所有接口。脚本不配置防火墙，Docker 发布的端口可能绕过 UFW/firewalld 规则；通过云防火墙限制公网访问，并为公网长期使用配置 HTTPS 反向代理。
